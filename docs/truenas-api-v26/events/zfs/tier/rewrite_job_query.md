# zfs.tier.rewrite_job_query

## Summary

Subscribe to ZFS rewrite job collection events (ADDED, CHANGED, REMOVED). On subscribe, sends ADDED for all existing jobs, then polls every 5 seconds and fires CHANGED when a job transitions state or REMOVED when it disappears.

This event is generated by a dynamic source. If you want to specify subscription params, subscribe to it using the name in the following format `zfs.tier.rewrite_job_query:{"param": "value"}`

## Required Roles

- `DATASET_READ`

## Schema

- Type: object

### Subscription parameters

- Schema name: `ZfsTierRewriteJobQueryEventSourceArgs`
- Type: object

No arguments — subscribes to all rewrite job lifecycle events.

### ADDED

- Schema name: `ZfsTierRewriteJobQueryEventSourceEvent`
- Type: object
- No Additional Properties
#### fields (required)

- Schema name: `ZfsTierRewriteJobQueryEventSourceEvent`
- Type: object
- No Additional Properties
##### fields (required)

- Schema name: `ZfsTierRewriteJobEntry`
- Type: object

Current job entry reflecting the latest lifecycle state.
- No Additional Properties
###### tier_job_id (required)

- Schema name: `Tier Job Id`
- Type: string

Rewrite job identifier in `dataset_name@job_uuid` format.
- Must be at least `1` characters long

###### dataset_name (required)

- Schema name: `Dataset Name`
- Type: string

ZFS dataset this job is operating on.
- Must be at least `1` characters long

###### job_uuid (required)

- Schema name: `Job Uuid`
- Type: string

Unique identifier for this rewrite job.
- Must be at least `1` characters long

###### status (required)

- Schema name: `Status`
- Type: enum (of string)

Current lifecycle state of the job. `COMPLETE` - All files in the dataset have been processed. `RUNNING` - Job is actively processing files. `QUEUED` - Job is waiting for a free execution slot (see `max_concurrent_jobs`). `CANCELLED` - Job was stopped via `zfs_tier_job.cancel`. Not resumable. `STOPPED` - Job was RUNNING but its process is no longer active (e.g. daemon restart). This state is computed on read and is never written to persistent storage. `ERROR` - Job halted due to an unrecoverable error. Use `zfs_tier_job.recover` to retry failed files.
